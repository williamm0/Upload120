  Copying sample bytes cannot close them.
  - NAL mix differs. Reference histogram {1: 1905, 19: 66, 32: 66, 33: 66, 34: 66, 35: 1971}.
  - Reference HEVC samples each start with an access-unit delimiter (NAL 35). The output does not, because that unit is inside the sample.
  - AVC SEI (NAL 6) differs. It is inside the sample, so it stays with the copied bytes.
  - Codec is h264 here and hevc in the reference.
  - Color signaling is bt709/bt709/bt709/tv here and bt2020/smpte2084/bt2020nc/tv in the reference. The reference values are in the HEVC VUI, which lives in the SPS bytes.
  - Video handler name is b'VideoHandler\x00' here and b'\x1fMainconcept Video Media Handler' in the reference (Mainconcept / Premiere).
  - First audio sample description count is 1 here and 2 in the reference. The extra mp4a is a second decoder config, not a second copy of the samples.
  - Output audio samples by mdat index: {0: 48}
  - Reference audio samples by mdat index: {0: 1541, 1: 17}
  - The reference's second mdat is not an unused marker. 17 audio samples are stored in it (17 of them are 6-byte 211004608c1c frames). Pointing new samples at that pattern would add audio the input does not contain, so this tool leaves the box unreferenced unless the input already pointed at it.
